# GPU SPH

Проект: Unity 6000.3.16f1, Universal Render Pipeline 17.3.0.

## Запуск

1. Открыть `Assets/Scenes/SPHMillions.unity` — сцена для миллионов частиц.
2. В Inspector объекта **GPU SPH Liquid** нажать **1 Million**, **2 Million** или **4 Million**, затем Play.
3. Кнопки Pause / Resume, Reset и Step управляют симуляцией. Правая кнопка мыши вращает камеру, колесо меняет расстояние.
4. Параметры находятся на объекте **GPU SPH Liquid**, компонент **SPH Simulation**.

Меню **RSPH → Create Container Demo** создаёт дополнительную сцену с уникальным именем. Существующая сцена остаётся открытой; закройте её вкладку/выгрузите из Hierarchy, если её камера тоже активна.

Пресеты задают соответственно `100³ = 1 000 000`, `128³ = 2 097 152` и `160³ = 4 096 000` частиц. Они включают **Auto Fit Particles**, подбирают расстояние и радиусы под контейнер, используют **Billboards** и один подшаг на кадр. Менять количество можно и вручную через Spawn Counts. При включённом Auto Fit Particles поля spacing/radius/smoothingRadius вычисляются автоматически: радиус частицы = 0.45 расстояния, радиус ядра = 2 расстояния. **Spawn Fill Fraction** задаёт долю длины каждой стороны контейнера, доступную начальному блоку.

**Render Every Nth Particle** влияет только на отображение: все частицы продолжают участвовать в SPH. **Hidden** отключает отрисовку для расчёта/профилирования. В интерфейсе отдельно показаны рассчитанное и отображаемое количество. После ошибочного ввода компонент остаётся включённым: исправьте настройки или выберите пресет/Retry.

## Устройство

`SPHSimulation.cs` управляет GPU-буферами и временем. `SPHSpatialGrid.cs` строит GPU-сетку: ClearGrid, BuildGrid (счётчики и локальные номера частиц), многоуровневый exclusive scan ScanCells/AddBlockOffsets, ScatterParticles. Затем `Shaders/sph.compute` выполняет CalculateDensityPressure, CalculateForces и Integrate. Initialize создаёт начальный блок. `types.hlsl` задаёт структуру частицы: position и velocity, по float4 (32 байта).

Плотность вычисляется ядром Poly6, давление — симметричным градиентом Spiky, вязкость — лапласианом. Масса частицы равна `restDensity * particleSpacing^3`. Отрицательное давление обрезается для устойчивости свободной поверхности. Гравитация задаётся в мировых координатах. Интегратор — semi-implicit Euler; шаг ограничен настройкой, оценкой CFL и вязкостью. После медленного кадра лишнее накопленное время отбрасывается, поэтому симуляция может замедлиться, сохраняя малый шаг.

Частицы упорядочиваются по клеткам в отдельном GPU-буфере. Соседи ищутся в 27 клетках; соседние X-клетки объединены в непрерывные диапазоны, поэтому достаточно девяти запросов строк. Фиксированной вместимости клетки нет; соседние частицы не отбрасываются при переполнении. Плотность и силы индексируются в порядке отсортированных частиц, интеграция записывает результат в буфер отображения. Индекс частицы не является постоянным идентификатором. Раздельные dispatch исключают изменение соседних позиций во время расчёта сил. В обычном кадре нет чтения частиц на CPU.

Для миллионов используются сферы-импосторы: два треугольника на частицу с реконструкцией нормали в пиксельном шейдере. В режиме Spheres доступна исходная объёмная сетка, существенно дороже при больших количествах. Billboard-отрисовка использует плоскую глубину квадрата; это приближение поверхности частиц.

Контейнер замкнут по всем шести граням, границы учитывают радиус частицы. Размеры и физические коэффициенты измеряются в локальных единицах компонента. Для ожидаемого масштаба физики оставляйте Transform Scale = (1,1,1). Изменения параметров через Inspector во время Play перезапускают симуляцию. После изменения публичных полей из C# вызывайте InitializeSimulation(), если менялись число частиц, радиусы, расстояние или контейнер.

Пределы: 16 000 000 частиц и 16 000 000 клеток. Дополнительно проверяются GPU Memory Budget MB (по умолчанию 1536 MiB), половина заявленной VRAM и максимальный размер буфера устройства. Основная память — 92 байта на частицу плюс 8 байт на клетку и небольшие буферы scan; это оценка буферов SPH без прочей памяти Unity. 256 потоков в группе позволяют обработать поддерживаемый диапазон без превышения 65535 групп на dispatch.

Это ограничения допустимых настроек, а не гарантия скорости или проверка всех 16 миллионов. На RTX 4070 проверены 1–4.096 млн. Скопление множества частиц в одной клетке всё ещё может ухудшить поиск до квадратичного. При уменьшении smoothingRadius стабильный физический шаг тоже уменьшается, поэтому большой расчёт может идти гораздо медленнее реального времени. Увеличение Max Substeps меняет объём работы на кадр, а не допустимый физический шаг.

Нужны compute shaders, GPU instancing и совместимый графический API (например, Direct3D 11/12 или Vulkan). WebGL не подходит. Не реализованы произвольные коллайдеры, взаимодействие с Rigidbody и восстановление гладкой поверхности воды; визуализация показывает отдельные частицы. Ограничение maxSpeed защищает от выбросов скорости, но слишком жёсткие параметры требуют меньшего шага.

## Проверки

Unity: **Window → General → Test Runner → EditMode**, сборка `RSPH.Tests`. Тесты запускают настоящий compute shader: аналитическая плотность, сохранение импульса парой, вязкость, границы, неполная группа из 65 частиц, переполненная клетка и три секунды падения жидкости. Отдельные проверки проверяют reset, освобождение буферов, независимые симуляции, ограничения сетки и соответствие размеров видимого контейнера. Два теста автоматически входят в Play Mode и выходят из него.

Дополнительно проверяются partial-block scan, три уровня scan, сохранение всех частиц при scatter, автоподгонка больших пресетов и границы отсечения billboard при неравномерном масштабе.

Финальный полный прогон в Unity 26.10.2026: **16 passed, 0 failed, 0 skipped**; C# и шейдеры не сообщают ошибок компиляции.

Замеры 26.10.2026, RTX 4070 / Direct3D12, начальное распределение, 2 прогревочных и 8 измеряемых шагов с синхронизацией GPU, без отрисовки:

| Частиц | Буферы SPH | Время расчёта шага | Физический шаг |
|---:|---:|---:|---:|
| 1 000 000 | 92.4 MiB | 3.94 мс | 0.376 мс |
| 2 097 152 | 193.9 MiB | 9.97 мс | 0.294 мс |
| 4 096 000 | 378.7 MiB | 12.17 мс | 0.235 мс |

Это время solver, не FPS. Дополнительные 3000 шагов на 4 096 000 частиц заняли 31.82 с и довели расчёт до 0.707 с физического времени. Полная GPU-проверка всех частиц после обоих блоков: ноль NaN/Infinity, ноль выходов из контейнера, ноль нарушений ограничения скорости. Сцену визуально проверили с отображением всех 4 096 000 частиц. Данные: `docs/sph-million-benchmark.json`; скриншот: `docs/sph-4million.png`.

Воспроизводимые тела команд для Unity MCP: `Tools/Benchmark-SPH.cs.txt` и `Tools/Stress-SPH.cs.txt`. Они запускаются в Play Mode, переключают пресеты и ставят расчёт на паузу; только диагностика считывает с GPU несколько значений. Шейдер проверки расположен в Tests/Editor и не нужен обычной симуляции.

Без подключения редактора можно запустить из корня `./Tools/Validate-SPH.ps1`. Скрипт компилирует runtime/editor/tests C# с установленными библиотеками Unity, все compute-ядра и обе стадии обоих шейдеров отрисовки DXC. Это проверка компиляции; она не запускает Unity и не подтверждает рендеринг. Параметры `-EditorData` и `-Dxc` задают другие пути.

Формулы основаны на [Müller, Charypar, Gross, 2003](https://matthias-research.github.io/pages/publications/sca03.pdf). Иерархический scan следует схеме [NVIDIA GPU Gems 3, Chapter 39](https://developer.nvidia.com/gpugems/gpugems3/part-vi-gpu-computing/chapter-39-parallel-prefix-sum-scan-cuda). Отрисовка использует [Unity Graphics.RenderPrimitives](https://docs.unity3d.com/6000.3/Documentation/ScriptReference/Graphics.RenderPrimitives.html) и RenderMeshPrimitives.

## Unity MCP

В `Packages/com.anklebreaker.unity-mcp` установлен официальный AnkleBreaker Unity MCP 2.41.4, исходный commit `3b28d4cea5911db575bbb5ab07f3241dfd024cf3`. Используется локальная UPM-зависимость: Git-загрузка через Package Manager встретила EPERM при переносе в кеш. Пакет можно открыть через **Window → AB Unity MCP → Dashboard**; его сервер должен запускаться автоматически. Node-сервер уже настроен в Codex. Пакет работает только в редакторе и не входит в player build.
